# 48 · 阈值校准表（把新证据转成可用判据）

> 生成日期：**2026-10-13**；基准版本 **1.6.2f1**。
> 上游证据：`references/47-operations-playbook.md`（新证据正文）、`references/00-sources.md`（来源编号 S##/C##）。
> **本表的作用**：逐条比对 `SKILL.md` §2 速查卡与 `references/30`/`40`/`45` 里的阈值，指出**哪些该改、改成什么、依据是什么**。
>
> 表格列义：
> - **原 skill 阈值** = 当前 `SKILL.md` §2 / 相关 references 里的写法
> - **新证据支持的值** = 本轮可引用的新口径
> - **置信度** = `高`（官方一手）/ `中`（可复现社区实证，或官方+社区互证）/ `低`（攻略站，需交叉验证）
> - **性质** = `[游戏机制]` / `[社区实证]` / `[攻略经验]` / `[待验证]`
> - **是否需改 SKILL.md** = `已改` / `建议改（未改，理由）` / `无需改` / `新增条`
>
> **修改纪律**：只改有证据支撑处。**与用户裁定顺序冲突的（攻略站 vs 游戏内实测）一律不采纳攻略站。**

## F. 一句话总结（给下游 AI 的执行要点）

1. **服务半径现在是"有单位的、会缩水的"** —— 报覆盖用**双口径**，修覆盖先**调预算**。
2. **货运有 4 条硬动作** —— 终端当配送中心 / 选址优先道路连接 / 出口走铁路船 / 缩短产业上下游距离。
3. **专业化工业有 2 个"不挑地"的选项** —— Livestock、Stone。
4. **单行道与"加密"都有隐含税基代价** —— 送货不足会停产；高密度必然加重交通。
5. **"每格税收""pcu/h""专用道提速"这三类数字，依然一个都不许给**；**单车载客量只有三个可信值
   —— 公交 80 / 地铁 1080 / 客运火车 840 人/辆**（**游戏内可信数值，玩家提供**，见 `40` 1.3 表），
   **且只用于容量归一与排序**；**其它方式（电车/单轨/渡轮/缆车）容量未知 → 不给、不归一**（见 N 节）。

## I. 【第四轮】C16「税率甜蜜点」——给玩家的可执行受控实验设计

> 背景：官方只有权衡句（"Lower taxes help buildings level up faster while higher taxes bring more money."），**三轮检索均无任何可复现受控实验**（第 3 次确认）。**本轮起不再追查，改为把这件工作交给玩家。**
> 目标：用一次 **2 个游戏月、只改一个变量**的对照，判出"**本城当前是否已经越过税率拐点**"。

**前提**（必须全部满足，否则结果不可用）
- 版本 ≥ 1.1.5f1（租金/升级机制已重写）；**记录版本号**。
- 选**两个规模、密度、建筑等级分布相近的相邻片区**（各 ≥ 200 栋可升级建筑），一个作**实验组**、一个作**对照组**。
- 两片区**共用同一套服务**（同一批学校/诊所/消防覆盖）；实验期间**不新增/不拆除服务建筑**、**不动预算滑块**、**不划新分区**。

**步骤**
1. **第 0 天（基线）**，两组分别记录：
   - `Building Level` 视图里 **L1/L2/L3/L4/L5 的建筑数量**（**核心观测值**）；
   - `Company Profitability` 视图里该片区的**平均利润 / 亏损公司占比**（⚠️ **必须在商业热门时段 10–19 时读数**；**凌晨 0–5 时的亏损不作证据** —— 商业盈亏随营业时段变化，见 N 节）；
   - `Land Value` 视图里两片区的**地价读数**；
   - 人口 / 劳动力 / 失业数；
   - 财政面板的**月度税收总额**。
2. **只改一个东西**：**实验组**的对应税率（**一次只测一类**：住宅 / 商业 / 工业 / 办公）**上调 +5 个百分点**；**对照组不变**。
3. **跑满 2 个游戏月**。（时间尺度参照：官方 1.1.6f1 的 workaround 说"办公税率 30% → 约 1 个游戏月清空全部办公公司"，可作为"升级/降级多久看得出来"的量级锚点。）
4. **第 2 个月末重记同一组数字**；有 Carto 导出时用 `city_report.py --prev` 出增量对比。

**判读表**

| 观察结果 | 说明什么 | 下一步 |
|---|---|---|
| 实验组 **L3+ 数量下降 ≥ 10%**、对照组基本不变，且**税收总额没升**（或升幅 < 3%） | **本城已越过拐点**：税率在吃掉自己的税基 | 把该类税率**降回原值 −3~5 pt** 再复测一次确认单调性 |
| 实验组 **L3+ 基本不变（±5% 内）**、**税收总额明显上升** | **尚未到拐点**，这一步加税是净收益 | 再 +5 pt 复测，**直到出现上一行的信号** —— 那就是本城税率拐点 |
| 实验组 **L3+ 下降**，但**税收总额上升更多** | **短期净赚、长期净亏**（升级是不可逆的税基投资） | 把税率留在**能维持 L3+ 不下降的最高档** |
| **两组出现同样变化** | 对照组没控住（两片区共用商业街/共用服务；或期间有开业潮） | 结果作废，换片区重做 |
| 实验组**住宅人口下降**而商业/工业没动 | 住宅税率已通过"付不满 upkeep"把住户挤走 | 先降住宅税，看 L 分布是否回升 |

**纪律**
- **一次只动一类税、只动 5 pt。**
- **必须留对照组。**"我感觉加税后升级变慢了"**不作为结论**。
- **实验期间不要同时改服务、预算、分区、公共交通** —— 任何一条都会污染结果。
- **把两次读数的六个面板数字回传给顾问**，即可给出**本城专属的税率区间**，而不是通用数字。

## K. 一句话总结（第四轮更新）

1. **服务覆盖现在有三个口径**：**游戏内着色有没有洞 → 官方 range 当自圈下界 → 拉预算 150% 试容量**。`capacity` 的计量口径官方没定义，**禁止反推压缩曲线**。
2. **服务建筑第一次有了"完整价签"**：半径 / 容量 / 噪声 / 岗位 / 学历 / 造价 / 维护七项齐全（官方 1.6 表）。
3. **水电费率是不对称负和杠杆**：涨 1% 亏 0.4% 公司效率与 0.1 幸福度，降 1% 只赚 0.2% 与 0.05。
4. **1.1.5f1 把里程碑奖金砍了 90%+** —— 老攻略的现金规划全部失效。
5. **`Heavy Traffic Ban` 的送货问题可以停止追查了**：官方从未写过，全站检索只有 3 处提及。
6. **税率甜蜜点仍然没有答案 —— 但现在有一份"两次读数、两个片区"的可执行实验设计**（§I）。

## L. 【分层目标】第 1 层「基础体检」的阈值与口径（本轮新增）

`SKILL.md` 的核心目标已改为**分层**：第 0 层城市规模持续扩大 → **第 1 层四项基础** → 第 2 层最大化税收。
`city_report.py` 的 **§0.5 基础体检**就是第 1 层的执行体。各项判据与其**来源等级**如下：

| # | 基础 | 判据 | 阈值 | 来源等级 |
|---|---|---|---|---|
| ① | 人口分布均衡 | 组团人口密度 > 全城中位 **N 倍** → 过密；单一组团人口份额 >**60%** → 偏弱；附报**归一化熵** | `N = 2.5` | **[经验]** 自定，非官方 |
| ② | 失业率 | **必须由玩家读游戏内 Unemployment**；Carto 只给 `岗位 ÷ 劳动力` 供需代理，合理带 **0.90–1.15** | 见左 | **[硬数据]** 失业率本身；**[经验]** 供需带 |
| ③ | 公交与规模匹配 | 500 m 站点覆盖人口 **<80%** → 不达标；**人口 ≥6 万却零轨道** → 偏弱。⚠️ **范围**：只含客运线路（`RoutePassenger`）与客运站点（`StopBus`/`StopSubway`/`StopPassengerTrain`）—— **地铁总站等 depot 不算车站；货运铁路/货运航线不并入**（见本文 §M） | 见左 | **[现实标准]** 覆盖半径（`90` §5）；**[游戏机制]** 轨道解锁里程碑（`30`） |
| ④ | 路网分级 | ⭐ **支路 : 干路（大路+主干）= 2.5–4 : 1**；**已解锁内**高速占**已解锁**路网 >**25%** → 提示。⚠️ **非解锁区高速是「地图自带资源」，必须先剔除再算这个比值（`SKILL.md` 「路网口径」条）** | 见左 | **[现实标准]** `references/50` 书 p153 校验比；**[经验]** 高速占比 |

### ⚠️ 判定口径的两条纪律（本轮确立）

1. **主判据必须用「比值」而不是「绝对密度」。**
   CSL2 的「米」与现实「米」不对应、人口规模也不对应（`references/50` 书 p393 已明确警告），
   所以「路网密度 km/km²」「公交线网密度 km/km²」这类**绝对密度与现实的 2–4 / 3–5 km/km² 不可直接比较**。
   * ✅ **可用**：`支路 : 干路` 这类**无量纲比值**（尺度无关，可直接对照现实校验比）；
   * ⚠️ **只作同城纵向比较**：绝对密度、人均指标 —— 报告里会显式标注，**不参与判定**。

2. **失业率不可用代理替代。**
   Carto **没有失业字段**（已核实全部图层：`Area_Boundary` / `Building_Boundary` /
   `Network_*` / `POI_Location` / `Route_Centerline` / `Zoning_Boundary`）。
   供需比 `岗位 ÷ 劳动力` 测不出**结构性失业**（学历与岗位不匹配），也区分不了
   「失业」与「出城就业」—— 后者在游戏里不计失业，但**同样不向本城缴税**。

### 门控规则（给下游 AI）

> **第 1 层任一项 `不达标` → 所有税收类建议一律降级为「暂缓」**，并明确写出是哪一项拖住了。
> 报告 §8.2（真实税基）与 §11（税基潜力）会自动带上 🚦 门控提醒。

## N. 线路效率与商业盈亏的判读口径（**只改口径，不改任何阈值**）

> 本节的每一项都**不新增量化阈值**，只登记"算法怎么算、样本怎么取、结论什么时候能下"。

| # | 指标 | 现口径 | 落地位置 |
|---|---|---|---|
| **1** | **线路效率** | **必须按单车容量归一**：`线路效率 = 乘客数 ÷（车辆数 × 单车容量）`。单车容量 = 公交 **80** / 地铁 **1080** / 客运火车 **840** 人/辆（**游戏内可信数值，玩家提供**）；**电车 / 单轨 / 渡轮 / 缆车容量未知 → 不做归一、留空**。**必须同时给「人/车」原值** —— 只按「人/车」横向排序会把"地铁车大"误读成"地铁低效"。使用率类判据仍以游戏内 Line 面板的百分比为准 | `40` 1.3 表；`30` A3.7；`70` 3.4 与 4；`46` T6 |
| **2** | **停用线路** | **`Vehicle == 0` 即停用**：**不做任何客流分析**（人/车、人·km、估算间隔、效率排序、客流合计与中位数），**只做线位分析**（走向 / 长度 / 站数 / 覆盖贡献 / 是否与既有走廊重复）；报告**单独列清单** + 两条处方（① 恢复配车 ② 撤线）。**不得混进"低效线路"** | `30` A3.8；`70` 3.4；`46` T6 |

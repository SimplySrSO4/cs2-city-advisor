# 110 · 交付格式规范（DOCX + XLSX）— **规范性文件**

> **本文件是 normative（规范性）的。** 凡本文件与其它章节、脚本注释或历史做法冲突，
> **一律以本文件为准**。改格式只改这一份 + `scripts/core/deliverable_style.py`（唯一实现）。
>
> 相关：`SKILL.md` §1 第 5 步（落交付物）、§1 第 6 步（自查交付）、§6（与其他技能配合）。

## 0. 一句话规则

**默认交付 = `DOCX 规划报告` + `XLSX 数据附录`。**
**Markdown 只在玩家明确要求时输出**，且此时**不**产出 docx/xlsx。

## 1. 交付形态决策表（**先查这张表再动手**）

| 玩家的说法 | 交付物 | 说明 |
| --- | --- | --- |
| 没说格式 / "出个报告" / "帮我看看" | **DOCX + XLSX** | 默认。不要再问"要什么格式" |
| "Word" / "docx" / "文档" / "正式报告" | **DOCX + XLSX** | XLSX 仍要给（数据附录是报告的支撑材料）|
| **"markdown" / "md" / "纯文本" / "贴到论坛/QQ/贴吧" / "我只要文字"** | **仅 Markdown（`.md`）** | **明确要求时**才走这条；**不产出** docx/xlsx |

> ⚠️ **玩家说了 markdown 就只给 markdown**，不要"顺便"再生成一份 docx：
> 那是没被要求的文件，属交付污染。

## 2. 字体（**中西文必须分别指定**）

| 用途 | 中文字体（`w:eastAsia`）| 西文/数字（`w:ascii` / `w:hAnsi`）| 等宽（`w:cs`）|
| --- | --- | --- | --- |
| 全部正文与标题 | **微软雅黑** `Microsoft YaHei` | **Calibri** | **Consolas** |
| 代码/路径/字段名/坐标 | 微软雅黑 | Consolas | Consolas |

**硬要求**：每个 run **必须同时**写入 `w:eastAsia` 与 `w:ascii`/`w:hAnsi`。
只设 `run.font.name` 在 Word 里中文会掉回宋体 —— 这是最常见的返工原因。
样式层面（`styles['Normal']`）与 run 层面**都要**设一遍。

## 4. 段落格式总表（**字号 / 行距 / 段距 / 缩进 —— 逐项照抄**）

| 元素 | 字号 | 加粗 | 颜色 | 行距 | 段前 | 段后 | 缩进 | 对齐 | 分页控制 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 封面主标题 | 30 pt | 是 | `#14366B` | 单倍 | 0 | 4 pt | 0 | 居中 | — |
| 封面副标题 | 14 pt | 否 | `#444C5A` | 单倍 | 0 | 28 pt | 0 | 居中 | — |
| 封面信息行 | 11.5 pt | 否 | 黑 | 单倍 | 0 | 6 pt | 0 | 居中 | — |
| 封面脚注 | 9.5 pt | 否 | `#777E8A` | 单倍 | 0 | 0 | 0 | 居中 | — |
| **一级标题**（章，`## `）| **17 pt** | 是 | `#14366B` | 单倍 | **16 pt** | 6 pt | 0 | 左 | **keepNext + keepLines** |
| **二级标题**（节，`### `）| **13.5 pt** | 是 | `#1B4B8C` | 单倍 | **10 pt** | 6 pt | 0 | 左 | **keepNext + keepLines** |
| **三级标题**（`#### `）| **11.5 pt** | 是 | `#215CA8` | 单倍 | 10 pt | 6 pt | 0 | 左 | **keepNext + keepLines** |
| **正文段** | **10.5 pt** | 否 | 黑 | **1.25 倍** | 0 | **6 pt** | **首行缩进 21 pt（= 2 字符 / 0.74 cm）** | 两端对齐 | widowControl |
| 列表项 · 一级 | 10.5 pt | 否 | 黑 | 1.25 倍 | 0 | 3 pt | 左 0.74 cm + 悬挂 0.42 cm | 左 | — |
| 列表项 · 二级 | 10.5 pt | 否 | 黑 | 1.25 倍 | 0 | 3 pt | 左 1.16 cm + 悬挂 0.42 cm | 左 | — |
| 引用块（`> `）| 10 pt | 否 | `#3A424E` | 1.2 倍 | 0 | 6 pt | 左 0.74 cm，左侧 3 pt 竖线 `#C8D2E0` | 左 | — |
| 图题 | 9 pt | 否 | `#555B66` | 单倍 | 2 pt | 12 pt | 0 | 居中 | keepLines |
| 表题 | 10 pt | 是 | `#1B4B8C` | 单倍 | 6 pt | 2 pt | 0 | 居中 | **keepNext + keepLines** |
| 页脚 | 8 pt | 否 | `#888E99` | 单倍 | 0 | 0 | 0 | 居中 | — |

> **缩进口径统一用长度（pt/cm）而不是"字符"**：Word 的"2 字符"随字号变，
> 而正文固定 10.5 pt，所以 **2 字符 = 21 pt = 0.74 cm**，写死即可。
>
> **段距与行距都不要用"段前段后自动"**（`space_before_auto`），
> Word 版本间表现不一致。
>
> **目录页（可选，默认开）**：结构 = `封面 → 分页 → 目录 → 分页 → 正文`。
> 目录标题**复用「一级标题」**规格，目录项**复用「列表项 · 一级」**规格
> （即 `h1` / `bullet1`），**不另立字号**。目录项取自正文所有 `## ` 级标题，按出现顺序。

### 4.1 分页控制（**必设，否则会出"标题孤在页尾"这类低级缺陷**）

| 项 | 规定 | 实现 |
| --- | --- | --- |
| 各级标题 | `w:keepNext` + `w:keepLines` | `deliverable_style.SPEC["h1"/"h2"/"h3"]["keep"]` |
| 图题 / 表题 | `w:keepLines`；表题另加 `w:keepNext` | 同上（`caption` / `tbl_caption` / `figure`） |
| 正文长段 | 只加 `w:widowControl`（孤行控制），**不加 keepNext** | 同上（`body`） |
| 表格行 | `w:cantSplit`（行不跨页）+ `w:tblHeader`（表头跨页重复） | `TABLE["cant_split"]` / `TABLE["repeat_header"]` |

> ⚠️ **写在"直接格式"（`pPr`）上，不写命名样式** —— 这样不动 `styles.xml` 的基准样式，
> "基准样式 正文字号 = 10.5 pt / 中文 = 微软雅黑"这类校验不受影响。
>
> ⚠️ **`keepNext` 不要滥用**：只给标题与图表题。给正文加会把整节挤到下一页，反而更难看。
>
> 📌 **这一层原本缺失**（实测 python-docx 直出的报告 `keepNext` = 0 处），
> 会导致"标题孤在页尾、图题与图分离"。现已由 `deliverable_style` 确定性写入。

## 5. 表格

| 项 | 规定 |
| --- | --- |
| 样式 | 全边框网格；`Table Grid` |
| 表头行 | 字号 **9.5 pt**、**加粗**、白字、底纹 **`#1B4B8C`**、居中、段后 1 pt、垂直居中 |
| 表体行 | 字号 **9.5 pt**、黑字、段后 1 pt |
| 单元格对齐 | 首列**左对齐**；其余列**居中**；纯数值列右对齐 |
| 边框 | 0.5 pt 实线 `#BFC6D2` |
| 列宽 | **固定布局**（`w:tblLayout type="fixed"`）；列宽合计 **≤ 16.2 cm** |
| 表宽 | 显式写 `w:tblW`（`dxa`），不要交给自动适应 |
| **行不跨页** | 每个 `w:tr` 加 `w:cantSplit` |
| 表头重复 | 跨页时表头行重复（`w:tblHeader`）|
| 表题 | 源稿若给出「**表 N-M …**」段落，置于**表格上方**；否则不加自动表题（`N` = 所在章号，`M` = 该章内序号，见第 13.3 节）|
| 空单元格 | 写 **`—`**（缺数据不得留空，也**不得写 `0`** —— 0 与"没有数据"必须可区分）|
| 空表 | 无数据的表**整表删掉**，不写"暂无数据" |

## 6. 图

| 项 | 规定 |
| --- | --- |
| 来源 | Markdown 里的 `![图题](相对路径)` |
| 宽度 | **16.2 cm**（满版心）；小图按原始宽高比等比缩放，**不得超过 16.2 cm** |
| 位置 | 段落居中，段后 2 pt |
| 图题 | **在图下方**，格式见第 4 节「图题」行；编号形如 `图 N-M  xxx`（`N` = 所在章号，`M` = 该章内序号，见第 13.3 节）|
| 找不到文件 | **不插占位图、不报错中断** —— 改插一行 9 pt 斜体灰字说明，并计入校验告警 |
| 格式 | PNG/JPG；**不要**转成 EMF/WMF |

## 7. 页脚

居中一行：`<报告名>  ·  第 N 页`，8 pt，`#888E99`。
页码用 `PAGE` 域（`w:fldSimple`），**不要**写死数字。

## 8. XLSX 数据附录

随 DOCX 一起交付，文件名 `<城市名>规划数据附录.xlsx`。

| 项 | 规定 |
| --- | --- |
| 工作表命名 | `序号-短名`（如 `1-概览`、`12-扩展地块`）；**≤31 字符**，去除 `[ ] : * ? / \` |
| 表数量 | 报告里每个**数据表**一张工作表，**按报告出现顺序**编号 |
| A1 标题 | 13 pt 加粗 `#14366B`；A2 写口径/来源说明，9 pt 斜体 `#666E7C` |
| 表头行 | 第 3 行（有说明时第 4 行）；**10.5 pt 加粗白字 + 底纹 `#1B4B8C`**，自动换行，居中 |
| 数据行 | **10 pt**；数值右对齐；文本左对齐 |
| 数字类型 | **必须写数字型**（不要把 `"1,234"` 写成字符串）；单位放**表头**，不放单元格 |
| 千分位 | 不写进单元格值；需要时用单元格数字格式 |
| 冻结窗格 | 冻结表头行（`freeze_panes`）|
| 列宽 | 按内容设定，**不使用默认宽度** |
| 空值 | 写 `—`（缺数据不得写成 `0`）|
| 首表 | 固定为 `1-概览`：报告的核心 KPI（指标 / 数值 / 单位）|

## 10. 交付前校验（**必跑，不许目测代替**）

```powershell
# 1) 结构校验（捆绑 LibreOffice / check_office）
<python> <office-skills>\scripts\check_office.py "<报告>.docx" --out checks_docx.json
<python> <office-skills>\scripts\check_office.py "<附录>.xlsx" --out checks_xlsx.json
# 2) 本 skill 自带的**格式合规校验**（字体/字号/缩进/列宽/表头底纹逐项比对本文件）
<python> -X utf8 scripts/export_report.py --check "<报告>.docx" "<附录>.xlsx"
# 3) 正文体检（纯净 / 自包含 / 编号统一 —— 规范性条款见第 13 节）
<python> -X utf8 scripts/core/text_lint.py "<报告>.docx"        # 多个文件可一次传入
```

`--check` 必须报 **`PASS`**。任何一项 `FAIL` 都要回去改 `deliverable_style.py` 后重新生成，
**不要**手工在 Word 里改（下次生成又没了）。

### 10.1 视觉精修（**有 dsh-univer-office 插件时必做**）

`--check` 只能证明"数值符合规范"，**证明不了"看起来对"**（换行难看、表格溢出、
标题孤在页尾、半页空白 —— 这些只有看渲染图才知道）。所以再加一道 Univer 逐页目视：

```bash
# 生成 Facade JS + 打印工具调用序列（详见 `references/80` §3.4）
<python> -X utf8 scripts/city_docx_polish.py \
    --docx "<报告目录>/<城市名>规划报告.docx" \
    --univer "<报告目录>/<城市名>报告.univer" --js-dir "<报告目录>/_univer_js"
```

随后按序调用：`univer_new → univer_worktree(create) → univer_import(docType="traditional")`
→ `univer_execute(polish_doc.js)` → ⭐ **`univer_screenshot` 逐页看图** →
`univer_execute(verify_doc.js)` → `univer_export` → **再跑一次 `--check`**。

**逐页看图要看这四件事**：
1. 标题有没有**孤在页尾**（keepNext 生效了就不该有）；
2. **图题与图是否同页**、表题与表是否同页；
3. 表格有没有**溢出版心**（列宽合计 > 16.2 cm 会在图上直接看出来）；
4. 有没有**半页以上的空白**（分页控制或 keepNext 用过头）。

> ⚠️ **`univer_import` 必须用 `docType:"traditional"`** —— 只有它保留 A4 页面设置；
> `modern` 会把页面几何改写成固定版式且**不可恢复**。
>
> ⚠️ **Univer 渲染器不显示 `PAGE` 域的数字**（截图里页脚是"第  页"）——
> 这是渲染限制，**域本身完好**，`--check` 的"页脚含 PAGE 域"仍 PASS。
> **不要为了让截图有页码而写死页码。**
>
> ⚠️ `.univer` 与 `_univer_js/` 是**过程产物**，归档时由 `city_archive.py` 清理（「归档」条）。

### 校验清单（人工过一遍）
- [ ] 每个 run 都同时设了 `w:eastAsia` 与 `w:ascii`？（中文有没有掉成宋体）
- [ ] 正文首行缩进是不是 **21 pt**？列表项是不是左 0.74 cm + 悬挂 0.42 cm？
- [ ] 每张表列宽合计 **≤ 16.2 cm**？有没有横向溢出？
- [ ] 表头行底纹是不是 `#1B4B8C` + 白字加粗？行有没有跨页断裂？
- [ ] 图是不是 ≤ 16.2 cm 且**题注在图下**？
- [ ] **标题/图表题设了 `keepNext`/`keepLines` 吗**？有没有"标题孤在页尾"？
- [ ] **逐页看过 Univer 截图吗**？（无插件时用 LibreOffice 转 PDF 目视代替，并在报告里说明）
- [ ] XLSX 每张表都冻结了表头？数值列是数字型不是字符串？
- [ ] 交付物数量对不对（默认 2 个；玩家要 markdown 时**只有 1 个 .md**）？
- [ ] **跑过正文体检了吗**（第 13.4 节，`scripts/core/text_lint.py`）？`SKILL.md`、`references/`、`铁律`、节号符号、修订注**零命中**？
- [ ] **正文纯净吗**？有没有 `本轮新增`、`上一版`、`由 X 改为 Y` 这类编写期注释（见第 13.1 节）？
- [ ] **编号统一吗**？（章节 `N.` / `N.M`、交叉引用「第 N 节」、图/表 `图 N-M` / `表 N-M`，全文无节号符号，见第 13.3 节）

## 11. PPTX（仅在玩家明确要 PPT 时）

## 12. 改格式的正确流程

1. 改**本文件**（规范）；
2. 改 `scripts/core/deliverable_style.py`（唯一实现常量）；
3. 跑 `export_report.py --check` 确认新规范被落实；
4. **不要**在 `analysis/` 或 `export_report.py` 里就地写死字号/颜色 —— 那会让规范与实现脱钩。

## 13. 正文规范：**纯净 / 自包含 / 编号统一**（规范性条款）

> 第 10 节的格式校验证明"**样式**对"（字体、字号、缩进、列宽、底纹）；
> 本节约束"**文本**对"。**两者都要过**，且同样**不许目测代替**。
> 本节适用于一切交付正文：DOCX、Markdown、PDF 转换件，以及 XLSX 附录的说明行。

### 13.1 正文纯净 —— **不写编写期注释**

最终文档**只写规范与结论本身**，**不得留下修订痕迹**：

| 禁止写法 | 例子 |
| --- | --- |
| 口径变更注 | `口径（… 修正）`、`由 X 改为 Y`、`旧口径作废` |
| 版本对比注 | `上一版只列了…`、`本轮新增`、`第 N 轮改动` |
| 过程自述 | `本次分析先…再…`、`我们决定采用…`（除非这本身就是结论） |

> **要登记口径变更时，改成陈述现状**：写「**当前口径 = …**」，而不是「由 X 改为 Y」。
> 口径的变更史留在 skill 的参考资料里，**不进交付文档**。

### 13.2 报告自包含 —— **读者没读过本 skill**

* 正文**不得**出现 skill 内部标签：`SKILL.md`、`references/xx`、`铁律 N`、脚本名与函数名；
* 需要读者理解游戏机制时，**直接把机制与数值讲清楚**（**带游戏版本号**），
  而不是让他去翻资料；
* 判据要写成**可自查的一段话**（查什么 → 怎么算 → 什么情况下不成立），
  不得依赖"见上文 / 见某文件 / 见参考资料"这类需要来回翻的指代；
* 一个验收问句：**"只把这个文件夹给玩家，他能不能看懂全部结论、并核对我引用的每个数？"**

### 13.3 编号统一 —— **全文只有一套**

| 用途 | 写法 |
| --- | --- |
| 章节标题 | `N.` / `N.M`（如 `3.`、`3.2`） |
| 正文交叉引用 | 「**第 N 节**」「**第 N.M 节**」 |
| 图 / 表 | `图 N-M` / `表 N-M`（`N` = 所在章号，`M` = 该章内序号）|

* **全文任何位置都不得出现 `§`** —— 包括页眉页脚、图题表题、脚注、XLSX 的 A2 说明行；
* **不得**出现 `见上文` / `见后文` / `见某文件` 这类指代（与第 13.2 节同一条纪律）。

### 13.4 交付前**正文体检**（**必跑**）

```bash
<python> -X utf8 scripts/core/text_lint.py <文件…>      # .md / .txt / .csv / .docx / .xlsx / .pptx，可一次传多个
<python> -X utf8 scripts/core/text_lint.py --dir <报告目录>   # 目录内全部正文文件
```

**退出码**：`0` = 零命中（可交付）；`1` = 有命中（先改文档）；`2` = 用法错误。

`city_archive.py --dir <报告目录>` 归档时会**自动调用同一套体检**，**有命中就中止归档**
（要硬归档得显式加 `--force`），详见 `references/80` 3.3。
**命中即先改文档，再交付** —— 不得记下来"下一版再改"。

| 命中 | 为什么要改 |
| --- | --- |
| `SKILL.md` / `references/` / `铁律` | skill 内部标签 → 违反 13.2 自包含 |
| 节号符号（section sign，13.3 禁用的那个字符） | 违反 13.3 编号统一 |
| `本轮` / `上一版` / `第 N 轮` / `修正为` 等修订注 | 违反 13.1 正文纯净 |

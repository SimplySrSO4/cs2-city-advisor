# 90 · 游戏机制与现实书籍的冲突裁定表

> 本文件是**两份资料的接口**：左侧是联网检索到的 CSL2 游戏机制（`00`–`40`，带官方来源与版本号），
> 右侧是两本中文规划书的 OCR 提炼（`50`《城市规划原理》第3版、`60`《城市快速公共汽车交通系统》）。
> **用途**：当书里的标准与游戏机制不一致时，按这里的裁定执行，不要临场发挥。
>
> （历史说明：本文件初稿写于两本书尚未完成 OCR 之时，当时结论是"扫描件无法读取"。
> 后续通过 Windows.Media.Ocr 管线**已完整提取两本书**，故本文件已按真实书籍内容重写。
> 提取过程与判定证据见 `55-book-unreadable-log.md`。）

## 0. 裁定顺序（用户明确的规则）

```
① 联网检索到的游戏机制（references/00–40，带官方来源与版本号）
        ↓ 游戏没有对应机制时
② 游戏内实测数值 / Carto 导出数据（references/70 + scripts/city_report.py）
        ↓ 游戏完全没规定时
③ 两本中文书（references/50、60 · 现实标准：GB50220-95 / GB50137-2011 / GB50180-93 / CJJ/T85-2002 / CJJ/T15-2011 等，成书 1993–2011）
        ↓
④ 你的常识（最后手段）
```

**三类标签必须严格区分，并在句中标明**：

| 标签 | 含义 | 写法要求 |
|---|---|---|
| `[游戏机制]` | 有 CSL2 官方来源，可在游戏内验证 | 必须给 URL 或版本号 |
| `[实算]` | 由 Carto 数据算出 | 必须给算法与数据来源 |
| `[现实标准]` | 来自规范/教材，**游戏内不存在对应规则** | 必须给书名+页码，并注明"需按游戏内单位另行校准" |
| `[推导/经验]` | 由机制推出的操作建议 | 必须说明"非官方公式/规则" |

> **绝对禁止**：把 `[现实标准]` 写成 `[游戏机制]`。玩家会照着教材数字在游戏里布线，然后发现完全不成立。

> 唯一可用的游戏内距离锚点：**1 格 = 8 m**（官方吸附说明）。
> 换算：500 m ≈ 62 格；800 m ≈ 100 格。

## 1. 直接冲突清单（**一律以游戏侧为准**）

| # | 主题 | 书里的说法（现实标准） | CSL2 的实际机制 | 裁定 |
|---|---|---|---|---|
| **X1** | **重复线路的处理方式** | 《BRT》书 p57–60：与骨干走廊**重复率 >85%** 的常规公交**删除**；**重复率 30–85%** 的**截断为"喂给"线**；重合 ≥5 个骨干站则调整走向 | CSL2 里**拆分/截断干线会拉长各线间隔**，而候车时间直接进入寻路成本；本项目实战数据出现过两次"拆分后总客流低于拆分前" | **以游戏为准。** "删线/截断"在游戏里必须**先并车再改线**：只有在能把车辆数并入主线、把主线间隔压下来时才做。**顺序是"先并车 → 后改线"，绝不先删线** |
| **X2** | **BRT 的成本优势** | 《BRT》书 p6：相对轻轨**投资减少 60%–80%**、建设周期缩短 50%–75%、运营维护成本降低 80%–90% | CSL2 没有"轻轨 vs BRT"对照表；实际量级接近：**Bus Depot ₡150K / 维护 ₡31K 月**、**Subway Yard ₡200K / ₡18K 月**；公交"深受城市交通状况影响"，地铁"快速高运力" | **不要引用这组百分比。** 游戏里选公交还是地铁，依据是**走廊密度与距离**，不是"更便宜" |

| **X5** | **站距** | 《规划原理》书 p156：「**公交平均站距在 500 m 左右为宜**」，市中心小些、郊区大些 | 官方**没有站距规则**。可确证机制：① 站点**提升周边地价**（密站有正效应，1.1.0f1 起）；② 每个多余的路口转弯**累加进长者的寻路成本**；③ 线路固定时**站越多单程越慢 → 同样车数下间隔越长** | **站距属现实标准。** 可用区间（须标注现实口径）：市中心 300–400 m、一般城区 500 m、郊区 600–800 m。**同时提醒玩家实测"加站后间隔是否还接受得了"** |

## 2. 书里可以直接用、且与游戏机制**不冲突**的判据（优先采用）

这些是"换了介质但逻辑不变"的规划原理 —— **用它们做诊断框架，用游戏数据填数值**：

| 判据 | 出处 | 在 CSL2 里怎么用 |
|---|---|---|
| **非直线系数**（线路实际长度 ÷ 起终点直线距离） | 《BRT》表 4-4 评价指标（网络功能权重 0.24） | **强烈推荐**：用 `city_report.py` 的线路长度与端点坐标实算。系数大 = 绕行 = 直接拖长间隔 |
| **平均步行到站距离** | 《BRT》表 4-4（服务水平里权重 0.3，第二重要项） | 用 Carto 建筑点 + 站点位置实算"加权平均步行距离"，比只看覆盖率更有意义 |
| **支路应远多于主干路** | 《规划原理》表 8-3 | 用 Carto `Category` 统计 `Small : Medium : Highway` 长度比，一眼看出是不是"只有主干道" |
| **相邻组团之间至少两条联系道路** | 《规划原理》书 p151 | 检查各区之间是否只有一条路/一座桥相连 —— 这是 CSL2 最常见的"一堵全城瘫"结构 |
| **停车泊位边际效益递减** | 《BRT》书 p77–79：设计 2/3/4/5 泊位，有效仅 1.85/2.60/3.25/3.75 | 游戏车站有**站台数上限**：不要盲目堆大车站，2–3 个站台通常够用 |
| **站距的取舍逻辑**（站距大 → 速度快但步行长；站距小 → 可达好但速度慢） | 《BRT》书 p77–79 核心论点 | 向玩家解释"为什么不要每 100 m 设一站"的最佳框架 |
| **"用地布局 → 客源 → 枢纽 → 网络"因果链** | 《规划原理》/《BRT》 | 反过来用：**先有需求再布线**。用于反驳"先修地铁再等人来" |
| **步行 5 分钟 ≈ 400 m、10 分钟 ≈ 800 m** | 两书通用换算口径 | 把书里所有"分钟"型指标翻译成游戏格数（÷8 m） |

## 3. 书里**不要**带进游戏的内容

1. **任何"人次/小时""万人次/h"量纲的运能目标**（BRT 1.5–2.5 万/h 等）—— 游戏不公布载客量，无法换算。
2. **信号优先、车外售检票、实时班次信息** —— 游戏没有对应功能（"准 BRT"上限见 X4）。
3. **容积率、建筑密度、日照间距**等控制性详细规划指标 —— 游戏没有这套参数。
4. **行政/法规/投融资/公众参与**类内容（《规划原理》第十三章、第十四章 AutoCAD）—— 与游戏无关。
5. **历史文化遗产保护、城市更新**类内容（《规划原理》第十二章）—— 游戏无对应机制。
6. **中国城市史与国外城市案例**（《规划原理》第一章等）—— 仅作背景，不进建议。
7. **交通调查与需求预测的完整流程**（《BRT》第三章 28 页）—— 现实中要入户 OD 调查，游戏里直接读 Carto 数据更快。

## 4. 每次出建议前的三问

1. 我引用的这个数字，是 `[游戏机制]`、`[实算]`，还是 `[现实标准]`？—— **必须写明。**
2. 如果它是现实标准，我有没有说"游戏内无对应机制、需按游戏单位校准"？
3. 如果它和游戏机制冲突（尤其 X1 的"删线/截断"、X5 的站距），我是不是**以游戏为准**了？

## 5. 本轮新增规范的可用参数（按核心目标筛选）

> 本轮的 7 份新资料都是**国标 / 行业规范**，比教材更权威，**但同样是现实标准**。
> 逐份提炼见 `references/51`–`59`。这里只留**会直接影响"用地/交通效率 → 税收 + 幸福度"**的条目。
> **统一规则：下表的数值一律不得写成游戏数值，只能作为"原则/量级/校验"使用。**

### 5.1 TB 10099—2017《铁路车站及枢纽设计规范》（已核对页面图像，详见 `56-tb10099-railway-station.md`）

| 参数 | 数值（现实） | 在 CSL2 里怎么用 |
|---|---|---|
| **客运站按客流分四类** | 最高聚集人数 H：特大型 ≥10000；大型 3000–10000；中型 600–3000；小型 ≤600（客运专线按高峰小时发送量 PH 另有四档） | **原则**：车站规模要匹配客流，**不要一开局就修最大的站**。CSL2 车站有站台数分级（Small 2 台 → City Central 14 台），按实际客流选级 |
| **设站门槛** | 城市人口 100 万以上、**客运量（最大月日均上下车总人数）约 13 000 人**时应设客运站；枢纽中小城市 8 000–10 000 人亦可 | **人数不可换算**（游戏不公布该口径）。只取"**达到一定客流规模才值得设独立客运站**"的原则 |
| **城际铁路站台长度** | 8 辆编组时按 **220 m**；高铁站台按 **50 m** | 量级参照。游戏里车站**占地**要花钱，**别为"气派"选超大站** |
| **站台宽度（特大型站）** | 岛式中间站台 **11.5–12.0 m**，侧式 **8.5–9.0 m** | 同上：**"最小够用"而非越大越好** |
| **站台高度** | 高铁/城际 **高出轨面 1.25 m** | 无游戏对应，**不要引用** |
| **站台端部最小宽度（曲线地段）** | 不宜小于 **5.0 m** | 无游戏对应 |
| **换乘** | 「构建以铁路车站为中心，与**轨道交通、公交车、出租车**衔接顺畅的综合交通枢纽，实现**零距离换乘**」；特大型/大型站房宜与**轨道站、长途汽车站、公交站合建为一体化枢纽** | **强可执行**：用 CSL2 的车站升级项做一体化 —— Train Station 加 **Subway Interface + Taxi Stop**；Terminus Station 加 **Bus Terminal + Tram Terminal**；Bus Station 加 Subway Interface。**换乘站把多次候车集中到一处，是提升幸福度性价比最高的投资之一** |
| **选址** | ① 符合枢纽总图；② **伸入或靠近客流中心，与城市融合发展**；③ 多站**避免集中在城市同一侧**；④ 综合比选 | **强可执行**：站点设在建筑/岗位最密处（用 `city_report.py` §6 腹地表验证）；多站分散到不同象限 |
| **车站是"土地综合开发平台"** | 9.1.3-4 明文；4.1.4「**客内货外**」 | **这就是 TOD**：车站周边 400–600 m 加密到中高密度（1.1.0f1 起站点影响地价）。**"同样的地装更多税基"的最直接手段** |
| **省地的立体做法** | 站房可做线平式 / 线上式 / 线下式 / **多层立体跨线式**；允许设**无配线车站**（仅供乘降） | CSL2 轨道可**地下/高架**，车站也有地面/高架/地下三类 —— **核心区用地下站几乎不占地面**，是最彻底的省地手段 |
| **铁路占地量级** | 说明：**修建 1 km 铁路平均占用 30–65 亩**（≈2.0–4.3 ha/km） | **量级参照**：提醒玩家铁路是"用地大户"，**先确认这条线能带来多少税基**再决定修 |

|---|---|---|
| **站点间距** | **120–400 m（15–50 格）** | 与 `51` 的"公交站服务半径 300–500 m"配套看：**站距是"线路上的间隔"，服务半径是"面上的覆盖"**，两者不能混 |

| ⭐ **候车时间公式** | **`E(W) = E(H)/2 × (1 + C²)`**（式 12.1，印刷 p277） | **最重要的单条**：`C²`=间隔变异系数平方。规律时 `C²=0` → 候车=间隔/2；乱序时 `C²=1` → 候车=整个间隔。**⇒ 不加车，只把车"开规律"，候车就能砍半** |

| ⭐ **公交优先的真实收益** | 雅典专用道 → 部分线路乘客 **+10%**；慕尼黑单点信号优先 → 出行时间 **−19%**；都柏林 → **均值没降、方差降了**；**苏黎世信号优先+AVL → 车速仅 +1.9 km/h**（表 17.4，印刷 p438） | **专用道的价值是"降方差、减串车"，不是"提车速"**。→ 在 CSL2 里上专用道的理由是**让间隔稳定（压 C²）**，不要说成"让车更快" |

| **线网设计 4 准则优先级** | ① 乘客等待时间最小 > ② 偏离最短路径最小 > ③ 空座时间最小 > ④ 车队规模最小（印刷 p328） | **排序即处方优先级**：先压候车，再压绕行，最后才谈省车 |
